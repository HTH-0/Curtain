# Z 2차 측정 결과: 가명 안내문을 붙였을 때 (평가 세트 v1)

측정일: 2026-11-01. 대상: 1차와 같은 263문장. 응답 모델: `gemini-3.5-flash-lite`. 바꾼 것은 하나이다: 가림 요청 앞에 고정 안내문(`ChatGateway.MASK_NOTICE`, AC-4.6)을 붙였다. 답 A는 1차의 것을 그대로 다시 썼고(`collect --reuse-a`), 답 B만 안내문을 켠 게이트웨이(`--gateway.mask-notice=true`)로 새로 받았다. 결정과 방식은 [DECISIONS.md](../../../DECISIONS.md) 2026-11-01에 있고, 원자료는 [z2/](z2/)에 있다. 1차 결과는 [report_z_v1.md](report_z_v1.md)이다.

## 요약

- **값 보존이 뚜렷하게 올랐다: 84.5% → 99.6%.** 요청 속 값(번호, 이름 등)이 답에 그대로 들어간 비율이다. 글자 비교로 센 코드 지표이고 95% 구간이 겹치지 않는다(1차 79.6~88.3%, 2차 97.9~99.9%).
- **복원 성공은 92.0% → 93.9%로 조금 올랐지만 구간이 크게 겹쳐서(88.1~94.7%, 90.3~96.2%) 차이가 있다고 말할 수 없다.**
- **쓸모(유지율)는 Jev 기준 56.8% → 73.7%로 올랐다.** 그러나 Jev는 사람 판정과 48.9%만 일치해 채택하지 않았다([report_z_v1.md](report_z_v1.md)). 참고값으로만 적는다. 이번에는 사람 판정을 하지 않았다.
- **응답이 중간에 끊긴 답은 26건 → 17건**으로 줄었다.
- 결론: 안내문은 가명 때문에 값이 빠지거나 바뀌는 문제를 거의 없앤다(코드 지표로 확인). 답의 쓸모가 사람 눈에도 좋아졌는지는 이번 데이터로 확정하지 못한다.

## 지표

| 지표 | 1차 (안내문 없음) | 2차 (안내문 있음) | 근거 |
|---|---|---|---|
| 값 보존 | 223 / 264 = 84.5% (79.6~88.3%) | 263 / 264 = 99.6% (97.9~99.9%) | 코드 |
| 복원 성공 | 242 / 263 = 92.0% (88.1~94.7%) | 247 / 263 = 93.9% (90.3~96.2%) | 코드 |
| 유지율 (참고) | 67 / 118 = 56.8% (47.8~65.4%) | 87 / 118 = 73.7% (65.1~80.8%) | Jev |
| 응답 잘림 | 26 | 17 | Jev 입력 표시 |

- 유지율의 분모는 답 A가 쓸 수 있다고 판정된 118문장으로 1차와 같다. 답 A와 그 판정을 1차 것으로 고정했으므로 차이는 답 B에서만 생긴다.
- 두 구간이 거의 맞닿아 있다(65.4%와 65.1%). 같은 문장을 짝지어 본 검정은 하지 않았다.

## 안내문이 답에 새어 나온 정도

"안내해 주신 지침에 따라"처럼 안내문을 직접 언급한 2차 답은 2건이었다. 가림, 자리표시자, 대괄호 같은 관련 표현이 든 답은 1차 B 22건, 2차 B 22건, 답 A 24건으로 같은 수준이다. 안내문이 답을 어색하게 만드는 부작용은 이 데이터에서 크지 않았다. 다만 단어 검색으로 센 것이라 정확하지 않다.

## 한계

1. **사람 판정을 하지 않았다.** 쓸모 개선은 Jev 참고값뿐이다. 사람 판정 20문장(1차 45문장 중 seed 20261101로 뽑음)을 하려고 시트와 화면을 만들어 두었으나([z2/human_judge.html](z2/human_judge.html)) 하지 않기로 했다(DECISIONS 2026-11-02, 이후 사용자 결정). 하게 되면 1차 사람 판정과 나란히 비교한다.
2. **Jev가 믿을 만하지 않다.** 사람과의 일치율 48.9%, 같은 답의 판정 반복 일치 약 73%. 유지율 상승이 실제인지는 알 수 없다.
3. **답 A 판정을 1차 값으로 고정했다.** Jev로 다시 채점하면 A 판정이 263문장 중 5개 달라졌다. 비교를 깨끗하게 하려고 1차 판정을 썼다.
4. **응답 모델이 하나이고 약하다**(`gemini-3.5-flash-lite`). 더 큰 모델에서도 같다는 근거는 없다. 안내문 한 종류만 시험했다.
5. **같은 세트를 두 번 재었다.** 안내문은 1차 결과를 보고 만든 개선이므로, 같은 세트에서 개선 폭을 말할 때는 과적합 가능성이 있다. 새 문장으로 확인하지 않았다.
6. 평가 세트는 가짜 데이터이고 실제 업무 요청의 분포와 다를 수 있다.

## 결론과 다음 작업

- 안내문은 기본 꺼짐으로 두었다(AC-4.6). 운영에서 켤지는 사용자가 정한다. 코드 지표상 켜는 편이 낫다.
- 사람 판정이 필요하면 `z2/human_judge.html`을 열어 20문장을 판정하고 CSV를 저장한 뒤 비교한다.
- 새 문장 세트로 확인하는 것은 확장 후보이다.
